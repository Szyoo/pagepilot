# 架构与安全设计

本文描述扩展的组成、运行模型、认证方式与安全约束。消息格式见 [protocol.md](protocol.md)，规则格式见 [rules.md](rules.md)。

## 组成

| 部分       | 职责                                                                                                                                                                                                                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| background | 门户登录与会话、实时通道、规则缓存、回放调度与状态机、可信输入驱动、上报队列                                                                                                                                                                                                                                   |
| content    | 元素定位、页面抓取、操作录制、合成输入、验证组件检测、条件判断                                                                                                                                                                                                                                                 |
| sidepanel  | 日常使用的主界面（点扩展图标直接打开，没有弹窗）：页头（连接状态、版本、「管理页」直达后台网站、设置）；四个页签：当前页（匹配规则与运行、抓取、录制；当前页没有规则时列出各规则的「打开页面」）、运行（进度、交还与「继续」、「打开页面」切回运行所在的标签页）、录制（步骤指引、检查与上报）、规则（搜索、确认、自动运行开关、「打开页面」）。「打开页面」进入规则所属的页面：地址取最外层第一个不含占位符的 `open` 步骤，否则由匹配网址推出；已经有标签页停在那个页面时切过去，不再新开；步骤失败暂停时可打开「请 AI 看看」面板；深色模式跟随系统 |
| options    | 门户登录、本地数据保险库（个人信息与凭据）、站点设置（输入方式、凭据可用域名）                                                                                                                                                                                                                                 |
| vendor     | `src/vendor/claude-bridge/`：从 claude-bridge 原样复制的浏览器客户端与聊天组件（来源版本与升级方法见该目录的 README），随扩展打包，不加载远程代码                                                                                                                                                              |

### 请 AI 看看

步骤失败暂停时，侧边栏「运行」卡片上有「请 AI 看看」：在侧边栏里打开 claude-bridge 的聊天组件，把中断的上下文交给 AI，用户可以继续追问。
- 地址自动发现（RPC `ai.bridge`，`src/shared/bridge-discovery.ts`）：设置页手动填写的 `bridgeUrl`（高级覆盖）> 后台 `GET /api/ai/status` 返回的 `bridgeUrl` > 构建期 `VITE_DEFAULT_BRIDGE_URL`（可空）。后台结果在 background 内存里缓存 5 分钟，登录、登出与设置变化时清空；未登录或后台不可达时按其余来源取地址、`available` 为 false。地址是 bridge 浏览器接口的 base；scope 用后台返回的（缺省 `pagepilot`），bridge 侧给它配一个无工具、不联网的 profile。
- 网站权限：地址不是构建期写进 `host_permissions` 的，就在用户点「开始分析」时 `permissions.request` 申请（与截图的 `<all_urls>` 合并成一次请求）；侧边栏打开时先发现地址并检查是否已有权限，保证请求在点击处理函数里立即发起。
- 身份：沿用门户会话 cookie。侧边栏对 bridge 的 fetch 带 `credentials: 'include'`，EventSource 默认 `withCredentials`（`eventsource-credentials.ts`）；扩展持有 bridge 站点的网站访问权限，`SameSite=Lax` 的 cookie 也会带上。bridge 返回 401 时提示先在普通网页里登录门户。
- 第一条消息由侧边栏用 `client.send` 发出（带只对这一轮生效的 `options.instructions` 系统提示），拿到对话后组件 `openThread`；之后的追问由组件直接发送。内容由 `src/shared/assist.ts` 生成：规则名称、失败步骤（序号、说明、类型、错误码与人话）、同一层前后各 3 步、PagePilot 建议的继续位置、页面地址（只留 origin + path）、页面上可见交互元素的概要。
- 页面概要来自 RPC `capture.inspect`：只返回给侧边栏、不上报后台、不需要登录；最多 120 个元素，每个只有标签、角色、名称或文字（60 字以内）与敏感标记，输入类元素只取标签/aria-label/placeholder，不取值，敏感元素不带文字。

## 运行模型

Manifest V3 下 service worker 会被随时回收，页面跳转会销毁 content script，因此：
- **回放状态由 background 持有**，每执行完一步就写入 `chrome.storage.session`，以 `runId` 标识。
- service worker 重新启动后，从 `storage.session` 读取未完成的运行并继续。
- 叶子步骤重试用尽仍失败时（`repeat` 循环体与重新登录除外），运行暂停交给用户；background 按失败后标签页是否跳转、当前网址与后续步骤的网址规则判断用户处理到了哪一步，用户确认后从该步继续（也可重试、跳过或任选一步），详见 [rules.md](rules.md) 的「步骤失败时暂停」。
- content 脚本（`page-agent`）只提供原语：定位、判断条件、执行操作、检测验证组件、抓取、录制监听，不保存流程状态；每一步由 background 下发命令。页面跳转后 background 发现脚本缺失时会主动注入。
- 跨标签页流程（`open` 新标签、`switchTab`）由 background 跟踪标签页，在目标标签页就绪后继续。
- iframe 内的目标：background 先在主 frame 解析 `locator.frame`（同源 iframe 直接进入）；链路经过跨域 iframe 时，逐个子 frame 尝试解析。跨域 iframe 内的元素不支持用于条件判断（`assert`、`if`、`repeat`、`waitFor`），只支持操作类步骤；真实输入时按 iframe 的 `src` 换算坐标。
- 同一标签页同一时间只运行一条规则；同一规则在多个标签页同时运行时各自独立计数。运行所在的标签页被关闭时，该运行中止。
- content 脚本不在 manifest 中声明匹配范围（否则会带上全部网站的访问权限）：用户为规则授予网站权限后，background 按已授权的网站动态注册脚本（所有 frame），运行时也会主动注入。
- `trigger: "auto"` 的规则在页面加载完成后检查并启动；同一规则在同一标签页 5 分钟内最多自动启动一次，避免循环触发。

## 输入方式

页面会通过 `event.isTrusted` 等方式识别脚本输入，因此提供两种输入驱动：

| 方式        | 实现                                                                                                  | 特点                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `trusted`   | `chrome.debugger` + CDP（`Input.dispatchMouseEvent` / `Input.insertText` / `Input.dispatchKeyEvent`） | 产生真实输入事件；需要可选权限 `debugger`，运行期间浏览器显示调试提示条 |
| `synthetic` | 在页面内派发 DOM 事件并设置表单值                                                                     | 无额外权限；部分网站可识别                                              |
- 选择顺序：站点设置 > 规则 `inputMode` > 默认 `auto`。
- `auto`：已授予 `debugger` 权限时用 `trusted`，否则用 `synthetic`。
- 规则要求 `trusted` 但权限未授予时，先提示用户授权；用户拒绝则该次运行失败，不自动降级。
- `trusted` 点击需要把元素坐标换算到顶层视口（含 iframe 偏移、滚动与缩放），点击前先把元素滚动到可见区域。
- 每次运行结束后立即 detach，减少调试提示条的停留时间。

## 认证

扩展与后台共用门户的账号与权限体系，沿用门户的网页会话 cookie，不使用令牌。
- 登录：用户在设置页输入门户账号与密码，扩展向 `POST <门户>/api/login` 提交；门户返回的会话 cookie 由浏览器保存，扩展不接触、不保存令牌，也不保存密码。
- 后台请求：WebSocket 握手、SSE、轮询、上报与 `GET <后台>/api/me` 都不带 `Authorization` 头，靠浏览器自动带上的会话 cookie，由后台前面的门卫识别身份；`/api/me` 返回的 `sub` 作为用户标识。
- 网站访问权限：需要带 cookie 请求门户与后台，扩展以可选权限申请这两个站点的访问权限，点击「登录」时在用户手势内授权。
- 会话过期：会话由门户决定有效期（约 7 天）；后台返回 `401` 或重定向到登录页时进入「未登录」状态，暂停同步与自动运行，提示用户重新登录。
- 权限：后台按用户的角色与权限决定下发哪些规则；扩展只缓存当前用户可见的规则。
- 登出：向 `POST <门户>/api/logout` 请求并清除本地登录状态，清除规则缓存，中止所有运行；本地数据保险库不清除，重新登录同一账号后继续可用。
- 切换门户用户时，规则缓存与运行记录按用户隔离。

## 本地数据保险库

个人信息（`profile`）与凭据（`secret`）只存在本机，不出现在任何上行消息中。
- 身份：由门户登录确认，无需额外口令；未登录时无法读写保险库。
- 存储：数据按门户用户隔离，明文存于本机浏览器的 `storage.local`（键为 `vault:<userId>`），不上报。
- service worker 被回收不影响保险库：数据在 `storage.local` 中，运行时按当前用户读取。
- 规则需要的数据缺失时，运行前提示用户补充。
- 每条 `secret` 绑定允许使用的域名列表（由用户在设置页维护）；在其他域名的页面上解析该凭据会直接失败。
- 支持导出与导入：备份是明文 JSON，请自行妥善保管。

## 安全约束

规则来自后台并会在用户的浏览器中操作网页、使用本地凭据，扩展端必须独立执行以下约束，不依赖后台的正确性：
1. **凭据只能填写**：`{{secret.x}}` 只允许出现在 `fill` 步骤的 `value` 中，出现在其他字段的规则会被拒收。
2. **凭据绑定域名**：填写时目标 frame 的源必须在该凭据的允许域名内。
3. **运行前确认**：规则首次运行、版本更新后其 `match`、`requires` 或 `inputMode` 发生变化时，先展示规则摘要（匹配网站、需要的数据、步骤数）请用户确认。
4. **自动触发需用户开启**：`trigger: "auto"` 的规则下发后默认不自动运行，用户在扩展中逐条开启后才生效。
5. **主机权限按需申请**：运行规则时只申请规则 `match` 涉及的域名；抓取、录制时只申请当前页面所在的网站；不申请全部网站。录制过程中跳到尚未授权的网站时，那个网站上的操作不会被记录，需要先在该网站授权。
6. **本地变量不上报**：`extract` 保存的值只在本次运行内使用，不进入 `runReport`。
7. **上报内容最小化**：`runReport` 的错误信息只包含错误码与步骤 ID，不包含页面文本、表单值或占位符解析结果。
8. **抓取与录制脱敏**：密码框、支付字段、验证码输入框、`autocomplete` 为凭据类的输入框不采集值；录制时用户在这些字段的输入替换为占位符（见 [rules.md](rules.md#录制)）。
9. **频率下限**：`repeat` 的实际间隔不低于扩展设定的下限（默认 3 秒），规则无法覆盖。
10. **发给 AI 的内容最小化**：「请 AI 看看」只在用户点「开始分析」后发送，内容见上文「请 AI 看看」；不包含任何输入框的值、本地数据（个人信息、凭据）、占位符解析结果与网址的查询串。发送前面板会说明将发送什么，发送后组件里能看到完整的第一条消息。
11. **截图可选、默认关**：附截图的勾选框默认不勾选并提示可能包含个人信息；勾选后才用 `tabs.captureVisibleTab` 截运行所在标签页（须是所在窗口的前台标签页）的可见区域。浏览器要求截图的扩展拥有 `<all_urls>` 或 `activeTab`，因此勾选时会在点击时一并申请可选权限 `<all_urls>`（这是第 5 条的唯一例外，内容脚本仍只按具体站点注册）；不授予就不截图。

## 防机器人验证与人工交还

扩展不尝试绕过验证码或其他人机验证，遇到时交还给用户：
- 回放期间持续检测常见验证组件（reCAPTCHA、hCaptcha、Cloudflare Turnstile、极验等）的出现；检测到时自动插入一次人工交还，等待验证组件消失或页面跳转后继续。
- 登录环节：规则可声明登录状态的判断方式（见 [rules.md](rules.md#登录状态)），已登录则跳过登录步骤；未登录时自动填写账号密码，提交由用户完成。
- 交还时 sidepanel 显示提示与「继续」「中止」按钮，并发送系统通知；`repeat` 条件满足时同样发送通知。
- 提示音默认关闭：只有用户在设置页打开声音开关，且规则步骤设置了 `sound: true` 时才播放；规则无法绕过设置页的开关。
- 用户在交还期间的操作不会被录制或上报。
