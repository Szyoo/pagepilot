# 手动验证清单

自动化测试（`pnpm test`、`pnpm test:e2e`）覆盖不到、需要真实浏览器、真实账号或真实第三方组件的部分。每条格式为“怎么做 → 期望结果”。示例地址统一用 `https://portal.example.com`（门户）、`https://app.example.com`（目标网站）或 `http://127.0.0.1`。

准备：本机 `.env` 里配置 `VITE_DEFAULT_BACKEND_URL` 与 `VITE_DEFAULT_PORTAL_URL`（见 `.env.example`），`pnpm build` 后在 `chrome://extensions` 打开开发者模式，加载 `.output/chrome-mv3`。不要加载 `.output/e2e*`，那是带测试权限的构建。

## 门户登录与会话

- [ ] 已用 `.env` 构建：设置页只需输入账号密码，点击登录 → 不弹权限申请，显示已登录及用户标识，密码输入框被清空；「高级」里能看到构建时的门户、后台与 AI 服务地址
- [ ] 未配置 `.env` 的构建：设置页填写门户地址 `https://portal.example.com` 与后台地址 `https://api.example.com`，登录 → 弹出网站访问权限申请；授权后显示已登录
- [ ] 拒绝网站访问权限 → 提示需要授权，仍为未登录
- [ ] 输入错误密码 → 显示“账号或密码错误”，仍为未登录
- [ ] 使用已过期的账号登录 → 显示账号已过期
- [ ] 短时间内连续多次登录失败 → 显示请求过于频繁
- [ ] 登录后查看 `chrome.storage` 与网络请求 → 不存在令牌或密码；后台请求不带 `Authorization` 头，只带会话 cookie
- [ ] 后台 `GET /api/me` 返回的 `sub` 与门户账号一致，扩展显示的用户标识与之相同
- [ ] 用没有扩展使用权限的门户账号登录 → 连接状态显示“当前账号无权使用扩展”，不同步规则
- [ ] 会话过期：在门户使该会话失效（或等待过期）→ 扩展变为未登录并提示重新登录，暂停同步与自动运行
- [ ] 用权限不同的两个账号先后登录 → 每个账号只看到自己可见的规则，切换后规则缓存、运行记录与保险库数据互不串用
- [ ] 断开网络后恢复 → 自动重连，不要求重新登录
- [ ] 登出 → 规则缓存清空、运行中止；保险库数据仍在，重新登录同一账号后可继续使用

## 调试权限与真实输入

- [ ] 首次运行 `inputMode: "trusted"` 的规则 → 弹出“调试”权限申请；拒绝后运行失败，提示需要调试权限
- [ ] 同意调试权限后运行 → 运行期间浏览器顶部出现“正在调试此浏览器”的提示条；运行结束（成功、失败、中止）后提示条消失
- [ ] 运行中用户点击提示条上的“取消” → 运行以失败结束，不卡住；之后再次运行可重新附加
- [ ] 目标页面已打开开发者工具时运行真实输入规则 → 仍能正常点击和输入，或给出明确的失败原因
- [ ] 在 `chrome://extensions` 里撤销调试权限后运行 `inputMode: "auto"` 的规则 → 改用合成输入，运行报告的 `inputMode` 为 `synthetic`
- [ ] 设置页把某个站点的输入方式设为“合成” → 该站点上即使规则要求真实输入也不附加调试器

## 目标网站对真实输入的识别

- [ ] 在会检查 `event.isTrusted` 的网站（例如自建的 `http://127.0.0.1` 测试页，或已知只接受真实点击的按钮）运行合成输入规则 → 网站不响应或判定为脚本操作
- [ ] 同一规则改为 `inputMode: "trusted"` → 网站正常响应点击、输入与回车，表单能提交
- [ ] 在带输入法、自动补全或输入掩码（如手机号、日期格式化）的输入框上用真实输入填写 → 最终值与规则一致，网站的校验提示正常更新
- [ ] 在跨域 iframe 内的按钮上用真实输入点击 → 点中的位置正确（坐标已换算到顶层页面）

## 验证码检测与人工交还

每种组件分别在含该组件的测试页（`http://127.0.0.1` 自建页面或组件官方的测试站点密钥）上验证：
- [ ] reCAPTCHA（v2 复选框与图片挑战）出现时 → 运行自动暂停，侧边栏显示交还提示及“继续”“中止”按钮，并收到系统通知
- [ ] hCaptcha → 同上
- [ ] Cloudflare Turnstile → 同上；无需交互即自动通过时，也能检测到组件消失并继续
- [ ] 极验（GeeTest，滑块或点选）→ 同上
- [ ] 用户完成验证后 → 组件消失或页面跳转，运行自动继续后续步骤
- [ ] 用户点击“继续”（组件仍在）→ 30 秒内不再重复触发交还
- [ ] 用户点击“中止” → 运行以 `aborted` 结束
- [ ] 交还期间用户在页面上的操作 → 不出现在录制结果和上报内容中
- [ ] 扩展从不自动点击或填写验证码组件

## 步骤失败时暂停

- [ ] 规则里某一步找不到元素 → 重试用尽后运行暂停，侧边栏显示“第 N 步「…」失败”、错误说明与「从第 N 步「…」继续」按钮，收到不带提示音的系统通知
- [ ] 不跳转页面、在页面上修好问题后点「继续」→ 重新执行失败的那一步并接着跑完
- [ ] 手动点到下一页（规则后面有等待跳转到该页的步骤）→ 一两秒内按钮变成从那之后的第一步继续；点「继续」后接着跑，运行报告里越过的步骤记为 `handedOff`
- [ ] 「跳过这一步」→ 从下一步继续，报告里该步为 `skipped`
- [ ] 「改从哪一步开始」下拉默认选中建议的那一步；选择其他步骤后点「从这一步继续」→ 从所选步骤继续
- [ ] 暂停期间点「中止」→ 运行以 `aborted` 结束
- [ ] 缺少本地数据导致失败 → 去设置页补上数据后点「重试这一步」→ 使用新数据继续
- [ ] `repeat` 循环体里的步骤失败 → 不暂停，照常进入下一轮

## 请 AI 看看

- [ ] 已在普通网页登录门户、配置了 AI 服务地址：步骤失败暂停 → 「运行」卡片有次要按钮「请 AI 看看」→ 打开覆盖页签的全高面板，「返回」可关闭
- [ ] 面板里「附上当前页面截图」默认不勾选；不勾选点「开始分析」→ 组件里显示发出的第一条消息（规则名称、失败步骤与前后几步、页面地址不含查询串、元素概要），没有输入框里的内容；随后显示 AI 的中文分析与该选「继续 / 重试 / 跳过 / 从第 K 步」中的哪一个
- [ ] 在组件里追问一句 → AI 接着回答；点「返回」后再回到运行卡片仍可「继续」
- [ ] 勾选截图：第一次弹出「访问所有网站」的权限申请；同意后第一条消息带一张当前页面的截图；拒绝则提示可以不勾选截图再试
- [ ] 勾选截图但运行所在标签页不在前台 → 提示先切到该标签页
- [ ] 门户会话过期或没登录门户 → 面板提示“请先在普通网页里登录门户”，「打开门户」打开门户地址；登录后点「重新检查」恢复
- [ ] 设置里清空 AI 服务地址（且没有构建默认值）→ 面板提示“还没有配置 AI 服务地址”，「开始分析」不可点
- [ ] 系统切到深色模式 → 面板与聊天组件一起变为深色

## 通知与提示音

- [ ] 默认设置下运行含 `sound: true` 步骤的规则并触发交还 → 只有系统通知，不发声
- [ ] 设置页打开声音开关后重复上一步 → 发出提示音
- [ ] 打开声音开关，运行未设置 `sound: true` 的规则 → 不发声
- [ ] `repeat` 等待条件满足（如刷新到有名额）→ 收到系统通知；`notify: false` 时不通知
- [ ] 系统层面关闭 Chrome 通知 → 扩展不报错，侧边栏仍显示提示

## 保险库

- [ ] 登录后在设置页录入个人信息与凭据 → 保存成功；`chrome.storage.local` 的 `vault:<userId>` 下是明文
- [ ] 未登录时打开设置页 → 保险库区域提示“请先登录门户账号”，无法编辑
- [ ] 切换到另一个门户账号 → 看不到前一个账号的个人信息与凭据
- [ ] 在 `chrome://serviceworker-internals` 停止扩展的 service worker 后再操作 → 保险库数据仍可读取
- [ ] 凭据只允许 `app.example.com`，在 `other.example.com` 运行填写该凭据的规则 → 运行失败，凭据未被填写
- [ ] 导出备份（下载前有明文提示）→ 在另一个浏览器配置里登录同一账号并导入 → 数据一致
- [ ] 导入内容不是有效备份的文件 → 提示“备份格式不正确”，现有数据不被覆盖
- [ ] 登出 → 保险库数据保留；重新登录同一账号后仍在

## 录制

- [ ] 第一次在某个网站点「抓取当前页面」或「开始录制」→ 弹出该网站的访问权限申请，授权后继续；拒绝 → 提示需要授权；在 `chrome://` 等浏览器内置页面上点击 → 提示这个页面不支持
- [ ] 在 `http://127.0.0.1` 测试页开始录制，依次点击、填写、选择、回车，停止录制 → 侧边栏列出对应步骤，定位器可读
- [ ] 录制时在密码框、银行卡号、验证码输入框以及 `autocomplete` 为凭据类的输入框中输入 → 录制结果里是占位符，不含实际输入值
- [ ] 录制过程中点击链接跳转到同站的另一个页面继续操作 → 录制不中断，包含 `open` 或导航后的步骤
- [ ] 录制过程中操作打开新标签页并在新标签页继续操作 → 录制结果包含 `switchTab`，后续步骤属于新标签页
- [ ] 停止录制并上传 → 后台收到 `recording` 消息，内容同样已脱敏
- [ ] 把录制结果作为规则回放 → 能从头到尾成功运行

## 自动化未覆盖的真实输入细节

`tests/e2e/trusted-input.spec.ts` 已在无头 Chromium 中验证真实输入的点击、填写与回车事件均为 `isTrusted`。以下仍需手动确认：
- [ ] 有界面的 Chrome（非无头）中运行真实输入规则 → 调试提示条按预期出现和消失
- [ ] 通过权限弹窗授予调试权限（自动化构建是直接声明的）→ 授权后无需重新加载扩展即可运行

## 侧边栏

- [ ] 点扩展图标打开侧边栏 → 页头显示连接状态圆点与文字（未登录灰、连接出错红、连接中黄、已连接绿并显示通道名）和版本号，版本号与 `chrome://extensions` 里一致
- [ ] 点页头「管理页」→ 新标签页打开后台管理页；在「录制」「运行」「规则」页签时分别直达对应标签页；未配置后台地址时按钮不可点
- [ ] 未登录 → 页头下方出现黄色提示“还没有登录门户账号”，点「去设置页登录」打开设置页；登录后提示消失
- [ ] 连接出错（例如临时断网）→ 出现错误卡片，点「重试」后恢复连接
- [ ] 「当前页」：打开匹配某条规则的网页 → 列出该规则；未确认时先展开确认摘要，确认后点「运行」才弹权限申请
- [ ] 运行进入交还 → 自动切到「运行」页签，黄色交还卡片有「继续」「中止」；用户手动切走后不会被再拉回
- [ ] 「运行」：进行中的运行显示已用时与（repeat 时的）轮数进度；结束后可「再运行一次」「清除」
- [ ] 「录制」：步骤指引随进度打勾；停止后检查步骤，丢弃需要行内二次确认；上报成功后出现「打开管理页」
- [ ] 「规则」：按名称或网址搜索；空状态区分“还没有规则”和“没有匹配的规则”
- [ ] 系统切到深色模式 → 侧边栏随之变为深色，文字清晰
